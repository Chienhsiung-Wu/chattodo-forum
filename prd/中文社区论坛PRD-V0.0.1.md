## 1. 背景与目标

### 1.1 背景

产品是一款 **AI + Agent + Todo 应用**（AI 原生处理用户待办），处于开发初期，需要官方社区作为**用户意见收集的主阵地**，同时承担新手答疑、Bug 收集、版本公告职能。选型 Discourse：开源、插件生态成熟、内置反垃圾与信任等级体系，官方支持账号委托登录（DiscourseConnect），可与 App 账号体系深度打通。

对标社区调研结论（猿料 / 飞牛论坛），优秀产品社区的三个共性：

1. **用户来了有收获**：社区不只是提意见的地方，要有用户能带走的东西。本产品与 uTools 高度类似——Prompt、Agent 工作流之于我们，正如插件之于 uTools，是天然的 UGC 供给侧；
2. **反馈发了有下文**：建议和 Bug 有可见的状态流转；
3. **官方在场且可见**：官方成员以实名分工身份常驻，响应及时。

### 1.2 本版本目标

1. App 用户零门槛进入论坛：账号一键打通，会员身份自动同步展示；
2. 建立完整反馈闭环：提建议 → 投票排序 → 官方标记状态 → 上线通知；
3. 官方团队以可见身份常驻，工作日 24 小时内首次响应；
4. 上线即有内容（含官方 Prompt / 工作流种子帖），避免冷启动；
5. 内测专区随首版上线，作为首个"来了有收获"型激励。

### 1.3 设计原则

- 分类宁少勿多，内容多了再拆；
- 只用官方维护的插件，控制升级维护面；
- 会员身份做成**配置即开的框架**：业务档位未定，论坛侧先把架子搭满；
- 一切多站相关设计（SSO、同步、配置）按双站预留，但 V0.0.1 只实施中文站。

## 5. 功能需求

### FR-1 账号体系：DiscourseConnect SSO（P0）

**需求描述**：论坛登录完全委托给 App 后端，关闭 Discourse 本地注册与登录。论坛账号通过 `external_id` 与 App 用户 ID 一一绑定。

**登录流程**：

1. 用户点击论坛"登录" → Discourse 生成带签名 payload，重定向到 App 侧 SSO 端点；
2. App 后端校验签名（HMAC-SHA256，共享密钥）→ 确认用户登录态（未登录先走 App 登录流程）；
3. App 后端将用户信息签名后回传 Discourse 回调地址；
4. Discourse 依据 `external_id` 创建或匹配论坛账号，完成登录。

**邮箱双轨方案（决策 #1）**：

- 有邮箱的用户：直传真实邮箱，可正常接收论坛通知；
- 纯手机号用户：App 后端生成**确定性占位邮箱**（如 `u{external_id}@users.<主域名>`），保证同一用户每次生成一致；
- Discourse 侧关闭邮箱验证（SSO 场景下以 App 数据为准）；
- 已知限制：占位邮箱用户收不到邮件通知，V0.0.1 接受，论坛内以置顶帖引导补填邮箱（在 App 侧补填后下次登录自动同步）。

**回传字段**：

| 字段 | 必填 | 说明 |
|---|---|---|
| external_id | 是 | App 用户唯一 ID，绑定锚点，不可变 |
| email | 是 | 真实邮箱或占位邮箱（见双轨方案） |
| username | 建议 | 取 App 昵称做合法化处理 |
| name | 可选 | 显示名称 |
| avatar_url | 建议 | HTTPS 直链 |
| add_groups / remove_groups | 是 | 会员群组同步，仅管理 `m-` 前缀群组（见 FR-2） |
| custom.member_type / member_since / member_expires | 建议 | 会员自定义字段，V0.0.1 传输存储、暂不渲染（为富展示预留） |

**多站预留（决策 #2/#3）**：App 侧 SSO 服务按"站点注册表"设计——每个论坛站点一条记录（site_id、独立 secret、回调地址）；sync_sso 推送按注册表扇出。V0.0.1 注册表中只有中文站，海外站上线时新增一条记录即可，App 端零改造。

**Discourse 侧配置**：`enable discourse connect` 开启；`discourse connect secret` 高强度随机并纳入密钥管理；关闭本地登录（`enable local logins` = false）；开启 email / username / avatar 的 SSO 覆盖。

**验收标准**：

- 已登录 App 的用户，从论坛点击登录到回跳完成登录态，全程无需输入账号密码；
- **纯手机号用户**可正常完成登录，不触发任何邮箱验证流程；
- 同一 `external_id` 反复登录命中同一论坛账号，昵称/头像变更下次登录自动同步；
- 论坛不存在本地注册、密码登录入口。

### FR-2 会员身份框架与同步（P0）

**设计目标（决策 #5）**：业务档位尚未定型（当前 free/paid，未来可能多档付费、永久会员、荣誉会员），论坛侧一次性搭好**可扩展的身份框架**，新档位"配置即开"，且展示尽可能丰富。

**群组架构**：

| 身份 | 群组名 | V0.0.1 状态 | 头衔 | 角标 | 管理方 |
|---|---|---|---|---|---|
| 免费用户 | 不入组 | — | 无 | 无 | — |
| 付费会员 | m-paid | **启用** | 会员 | 会员图标 | SSO 自动 |
| 多档付费 | m-pro / m-max（示例） | 预留 | 按档位命名 | 分档图标 | SSO 自动 |
| 永久会员 | m-lifetime | 预留 | 永久会员 | 专属图标 | SSO 自动 |
| 荣誉会员 | h-honor | 预留 | 荣誉会员 | 专属图标 | **论坛侧手动授予** |
| 内测用户 | beta | 启用 | 内测体验官 | 可选 | 论坛侧手动 |

**关键约定——前缀隔离**：SSO 的 `add_groups` / `remove_groups` **只管理 `m-` 前缀群组**；`h-` 前缀（荣誉类）与 `beta` 由论坛侧独立管理，永远不进 SSO 的 remove 列表。这样会员到期不会误删荣誉身份，两类身份可自由叠加。

**展示规则（用满 Discourse 原生能力）**：

1. **头衔（title）**：用户可在个人设置中，从其所属全部群组的头衔里自选一个展示——多身份并存时用户自己决定亮哪个；
2. **角标（flair）**：取主群组（primary group）图标，SSO 同步时按优先级设置主群组：荣誉 > 永久 > 高档付费 > 付费；
3. **用户卡片与个人主页**：原生展示用户所属全部群组徽章，多身份一目了然；
4. **荣誉会员墙**：`h-honor` 群组开放公开成员列表，形成可浏览的荣誉榜页面；
5. **富展示预留**：SSO 传入的 `member_type / member_since / member_expires` 自定义字段先存储；V0.x 用一个轻量主题组件把它们渲染成用户卡片上的"会员信息卡 + 多徽章横排"（列为下版本第一优先的展示增强）。

**同步机制**：

1. 登录时同步：SSO payload 携带群组与自定义字段，登录即校正；
2. 实时同步：App 后端在会员开通、升级、到期事件中调用 `sync_sso` 管理 API 推送（按站点注册表扇出）；
3. 兜底：登录时同步天然覆盖漏推场景。

**验收标准**：

- 付费会员发帖后，用户名旁可见头衔、头像可见角标；用户卡片展示其全部群组徽章；
- App 内完成会员升级后 1 分钟内，论坛群组、头衔、角标更新；
- 会员到期后，下一次同步移除 `m-paid`，但**手动授予的 `h-honor`、`beta` 不受影响**；
- 新增一个会员档位的全部工作 = 建群组 + 配头衔角标 + App 侧映射表加一行，无需论坛代码改动。

**玩法分享（决策 #6）**——本产品的"猿料时刻"，四个内容方向作为分类内标签：

| 标签 | 内容 | 示例 |
|---|---|---|

- 内测版本发布帖、专属反馈收集均在专区内进行；泄密与外传条款写入招募帖。

### FR-4 反馈闭环（P0）

#### 4.1 功能建议投票：Topic Voting 插件

- "功能建议"分类启用官方 Topic Voting 插件，每个话题顶部出现投票按钮；
- 用户可用票数有限（随信任等级增长，默认配置），迫使用户做优先级取舍；
- 建议完成并关闭话题后票数自动退还；
- 分类默认按票数排序，产品团队每周据此评审。

#### 4.2 状态标签

仅 staff 可用的标签组 `status`：

| 标签 | 含义 | 使用时机 |
|---|---|---|
| 已计划 | 进入排期 | 产品评审通过后 |
| 开发中 | 正在实现 | 进入开发时 |
| 已上线 | 已发布 | 发版后，话题内回复版本号并 @ 提出者 |
| 暂不考虑 | 近期不做 | 附一句原因，保持透明 |

**运营要求**：新建议两周内获得任一状态或官方回复；发版公告回链对应建议话题并 @ 原提出用户。

#### 4.3 已解决标记：Solved 插件

"使用问答""Bug 反馈"启用官方 Solved 插件；提问者或官方可标记答案，答案摘要置顶于首帖下方，已解决话题带 ✔ 标识。

#### 4.4 Bug 反馈话题模板

强制模板（全文见附录 A），针对 AI 产品特性增加"AI 相关信息"区块（指令内容、AI 回复截图脱敏后提供）。目标：信息完整、无需追问即可定位的 Bug 帖占比 > 70%。

#### 4.5 内置投票（Poll）

启用内置 Poll（单选/多选/评分，可匿名、可定时截止），供官方快速调研。无需额外插件。

### FR-5 团队协作与通知（P0）

- **Webhook 推送（决策 #7）**：Discourse Webhook 将"功能建议""Bug 反馈"新话题实时 POST 到一个轻量中转（云函数即可，约 50 行代码），中转将 JSON 适配为目标 IM 的自定义机器人消息格式。飞书 / 钉钉 / 企业微信 / Slack 接入方式同构，实施时确定目标地址即可，不构成方案分支；
- **邮件通知**：接入国内 SMTP 服务（见第 6 节），支撑回复通知与摘要邮件；
- **响应 SLA（上线条件）**：工作日 24 小时内对新反馈完成首次官方回复。SLA 承诺"首次响应"而非"解决"，用状态标签管理预期。

### FR-6 上线前内容与基础配置（P0）

**种子内容**（上线前完成，≥ 18 帖）：

| 版块 | 内容 | 数量 |
|---|---|---|
| 公告 | 社区规则与导览、产品路线图预告、团队介绍、内测招募帖 | 4 |
| 使用问答 | 官方 FAQ（安装、账号、AI 功能常见问题等） | 8~10 |
| Bug 反馈 | 已知问题清单（含状态），示范模板用法 | 1~2 |
| 功能建议 | 官方发布 2~3 个真实规划中的建议并打状态标签，示范闭环 | 2~3 |
| 玩法分享 | 官方 Prompt 精选包 1 篇、Agent 工作流示例 2 篇、AI + GTD 方法论 1 篇 | 4 |

**官方身份配置**：官方账号统一实名分工头衔（"产品同学""开发同学""运营同学"），staff 名字高亮，确保在反馈区可见。

**基础配置**：中文语言包与中文分词搜索（官方自带）；信任等级默认配置（配合 SSO 实名绑定，垃圾内容成本已高）；品牌轻定制（Logo、favicon、主色调）。

## 6. 非功能需求与部署（中文站）

| 项 | 要求 |
|---|---|
| 服务器 | 大陆云厂商，2 核 4G 起步，预留升配 |
| 域名 | `bbs.<主域名>`（占位，随备案最终确定），强制 HTTPS |
| ICP 备案 | **关键路径**：域名 + 服务器同厂商办理，周期通常 1~3 周，立项即启动（见第 8 节 W0） |
| 邮件 | 国内商业 SMTP（如阿里云邮件推送 / SendCloud），配置 SPF / DKIM / DMARC，上线前多邮箱实测送达 |
| 镜像与依赖 | Docker 镜像在大陆网络环境下配置镜像加速源 |
| 备份 | Discourse 每日自动备份，同步至对象存储（OSS）异地保存，上线前验证可恢复 |
| 安全 | SSO 密钥纳入密钥管理并支持轮换；管理员账号强制 2FA |

**海外站预留（V0.0.2+）**：中文站打法验证后，以"备份恢复 + 站点设置导出"克隆建站；`forum.<主域名>`、海外主机、Mailgun 类邮件服务、英文语言包；App 侧仅需在 SSO 站点注册表新增一条记录。公告类内容双站同步发布纳入运营 SOP。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 备案周期超预期 | 上线延期 | W0 立项即提交；里程碑设计为备案与开发并行，仅 W4 切正式域名依赖备案 |
| 冷启动无人发帖 | 社区氛围死循环 | 18+ 种子帖前置；App 内入口引导；官方快速响应制造"发帖有回音"口碑；内测资格激励 |
| 邮件进垃圾箱 / 送达失败 | 通知失效 | 商业 SMTP + SPF/DKIM/DMARC；上线前多邮箱实测；占位邮箱用户引导补填 |
| SSO 密钥泄漏 | 任意账号伪造登录 | 密钥管理系统存储、定期轮换、泄漏应急预案 |
| SSO 误删手动身份 | 荣誉/内测身份丢失引发客诉 | `m-` / `h-` 前缀隔离约定；联调时加专项用例（FR-2 验收项） |
| UGC 泄露用户隐私 | 待办内容含个人信息被公开 | 玩法分享分类描述内置脱敏提醒；举报处理 SOP；官方示范帖以脱敏为范例 |
| 版本升级破坏插件 | 功能不可用 | 仅用官方插件；升级前备份 + 灰度验证 |
| 反馈量超出处理能力 | SLA 失守 | SLA 只承诺首次响应；状态标签透明化预期；周评审消化建议池 |
| 会员同步链路故障 | 身份展示错误 | sync_sso 调用加告警；登录时同步兜底校正 |

## 附录 C：会员身份配置速查

| 群组 | 由谁管理 | SSO remove 是否可移除 | 头衔 | 进入角标优先级 |
